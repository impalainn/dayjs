# CLAUDE.md — dayjs

Day.js: a ~2KB immutable date library with a Moment.js-compatible API. A tiny core plus opt-in plugins and locales, each shipped as its own file.

## Layout
- `src/index.js` — the core: `Dayjs` class + `dayjs()` factory. `src/utils.js`, `src/constant.js` are shared helpers.
- `src/plugin/<name>/index.js` — one folder per plugin (37). `src/locale/<code>.js` — one file per locale (143).
- `types/` — **hand-written** `.d.ts` files, not generated. `types/plugin/<name>.d.ts` must exist for every plugin.
- `build/index.js` — Rollup bundles each locale/plugin separately, writes `dayjs.min.js`, copies `types/` to root. `build/esm.js` post-processes `npm run babel` output.
- `test/` mirrors `src/`: `test/*.test.js` (core), `test/plugin/<name>.test.js`, `test/locale/<code>.test.js`.
- `docs/` — translated READMEs only; the real docs site lives in another repo.

## Commands (Node LTS)
- Install: `npm ci` — **not** `npm install`, which rewrites `package-lock.json` (~1300 lines of churn).
- One test file: `TZ=UTC npx jest test/plugin/isToday.test.js --coverage=false`
- Full suite, fast: `TZ=UTC npx jest --coverage=false`
- What CI runs: `npm run lint && TZ=UTC npm test` — 8 timezone-pinned runs, then the full suite with a **100% line-coverage** gate.
- Lint: `npm run lint` (ESLint 4, airbnb-base). No auto-fix script; `npx eslint --fix src test` works.
- Build: `NODE_OPTIONS=--openssl-legacy-provider npm run build` (the flag is required on Node ≥17 or the `size` step crashes with `ERR_OSSL_EVP_UNSUPPORTED`). ESM build: `npm run babel`.

## Conventions
- Style: **no semicolons, no trailing commas**, 2-space indent, single quotes, imports without file extensions.
- Plugin shape: `export default (o, c, d) => { c.prototype.foo = function () { ... } }` — `o` options, `c` the Dayjs class, `d` the `dayjs` factory. Wrap existing methods by saving `const oldX = proto.x` and calling it.
- Tests import from source (`import dayjs from '../../src'`), never from `'dayjs'`. Locale files do `import dayjs from 'dayjs'`; `test/__mocks__/dayjs.js` redirects that to `src`.
- Test idiom: `MockDate.set(new Date())` in `beforeEach`, `MockDate.reset()` in `afterEach`, and compare against moment as the oracle: `expect(dayjs(x).format()).toBe(moment(x).format())`.
- Locale file: first line must be `// Language Name [code]` (parsed by `test/locale/keys.test.js` and the build); `name` is lowercase and equals the filename; `relativeTime` needs all 13 keys; end with `dayjs.locale(locale, null, true)` and `export default locale`.
- Adding a plugin = `src/plugin/<name>/index.js` + `types/plugin/<name>.d.ts` + `test/plugin/<name>.test.js`. `test/plugin/declarations.test.js` fails without the `.d.ts`.
- Commits: Conventional Commits (`fix(plugin): …`, `feat: …`, `docs: …`) — semantic-release derives versions from them.

## Guardrails
- **Unset `TZ` makes tests fail on a clean checkout** (e.g. 7 failures in America/Los_Angeles near a DST change). Don't "fix" source to make those pass — rerun with `TZ=UTC` first. If a TZ bug is real, reproduce it with the `TZ=…` runs in `npm test`.
- Never edit build output: `/dayjs.min.js`, `/locale/`, `/plugin/`, `/esm/`, `/index.d.ts`, `/locale.json` (all gitignored, regenerated by build). Edit `src/` and `types/`.
- Core size budget: `dayjs.min.js` must stay under 2.99 KB gzipped (currently ~2.79 KB). Put new features in a plugin, not `src/index.js`.
- Don't edit `CHANGELOG.md` (semantic-release writes it), don't bump `version` (stays `0.0.0-development`), don't run `npm audit fix` (it upgrades the pinned toolchain).
- Work targets the `dev` branch; pushes to `master` trigger an npm release.
